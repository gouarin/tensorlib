# Communication in the evaluation plan

Type: grilling
Status: resolved
Blocked by: 18, 22, 24

## Question

[Kernel IR](22-kernel-ir.md) puts communication in the evaluation plan, never in a kernel, and [ADR 0004](../../../docs/adr/0004-automatic-ghost-updates-in-the-graph.md) has the graph insert ghost exchanges on its own. Decide how the plan places and runs communication nodes, with the MPI backend left to implement but its hooks fixed:

- ghost exchanges: when an exchange overlaps with interior computation (split a kernel into interior and boundary segments, using the several bodies of the Kernel IR), how exchanges for several tensors and several windows are aggregated into one message per neighbour, and when a stale ghost region is refreshed (eagerly after a write, or lazily before a read);
- reductions across ranks: a plan node after the local reduction, blocking or non-blocking (`MPI_Iallreduce`), how several reductions of one window are packed into one collective, and how the poison status of [ADR 0007](../../../docs/adr/0007-errors-poison-results-across-ranks.md) rides along;
- redistribution as a plan node: which redistributions of [Distribution kinds](18-distribution-kinds.md) exist in v1 and whether they can overlap with computation;
- the tensorlib communication interface the plan calls (point-to-point, collectives, GPU-aware buffers, device streams, Kokkos Comm later), and what a serial or single-rank build does with these nodes;
- determinism: every rank must build the same plan, so placement rules may only depend on data that is identical across ranks.

## Answer

Decided with the user on 2026-10-30 and 2026-10-31. Exchange point and communication pattern are in `CONTEXT.md`. The interface and the progress model are recorded in [ADR 0010](../../../docs/adr/0010-persistent-communication-patterns-and-a-progress-thread.md).

- **When ghosts are refreshed.** An exchange exists only if a kernel of the evaluated window reads stale ghosts. If the writer is in the same window, the send moves right after it: the writer computes its boundary band, the send starts, then the writer computes its interior. If the writer was in an earlier window, the exchange is posted just before the reader, which computes its interior while the messages travel and its boundary band after the wait. No exchange stays in flight after an evaluation ends. A later `tl::prefetch_ghosts(u)` could start one across windows without changing this model.
- **Overlap.** The plan splits a kernel into interior and boundary launches when its interior has more than `TL_OVERLAP_MIN_CELLS` cells. The default is set per backend, and `TL_OVERLAP=always|never|auto` overrides it. Both orderings are in the cached plan, and the choice is made at launch from the extents. The split never changes the messages, so it is a local decision that may differ between ranks. Calibration was added to [Rerun the fusion benchmark on an HPC node and a GPU](19-rerun-fusion-benchmark-hpc-gpu.md).
- **Aggregation.** Each exchange point sends one message per neighbour. Every exchange placed at that point whose distribution has a congruent communicator and the same process grid shares it, even with different ghost widths. Exchanges at different points stay separate, and no send is delayed to join another.
- **Packing.** Generated pack and unpack kernels: ordinary kernel IR, compiled and cached like any kernel, with one pack per exchange point covering every tensor and neighbour of the message. Buffers are contiguous and come from the memory resource of the space. The message format belongs to tensorlib: a header with the poison flag of [ADR 0007](../../../docs/adr/0007-errors-poison-results-across-ranks.md) and the plan hash, then the bands in an order fixed by the plan. A later optimisation can fuse the pack into the writer's boundary launch as extra stores without changing the interface. The unpack stays separate so the ghost band is always coherent for `local_part_with_ghosts()` and PETSc DMDA local vectors.
- **Neighbours.** One phase, with direct messages to every neighbour of the stencil shape: 2d for `star`, 3^d - 1 for `box`. All messages are posted and waited for together. A neighbour that is the rank itself (a periodic axis with one rank) becomes a local copy kernel. Dimension-by-dimension sweeps could be added later behind the interface.
- **Reductions across ranks.** Each exchange point has one non-blocking collective. It packs every reduction whose local result is ready there, plus the poison status word (combined with OR) and the plan hash (min and max). The core generates the combining operation from the combiners, traced ones included. Completion is an event, so a consumer such as a 0-d `dt` stays on the device, and a host read waits for the event. Local results go through the host in v1; a device path for large partial reductions can come later. Ranks with an empty local part contribute the identity.
- **Reproducibility.** By default, an MPI non-blocking allreduce with the non-commutative tensorlib operation. Under `TL_FP=strict`, or for a reduction wrapped in `tl::deterministic(...)`, a fixed-shape binary tree in rank order over point-to-point, then a broadcast. This guarantees the same bits on every rank and from run to run at a fixed rank count. The promise of [Code-generation strategy](12-code-generation-strategy.md) becomes "reproducible at a fixed rank count, guaranteed under `TL_FP=strict`", the same rule as indirect scatter-add.
- **Redistribution.** v1 covers four cases:
  - replicated to block, with no communication;
  - block to replicated (allgatherv);
  - block to local on one rank and back (gatherv, scatterv);
  - block to block with another process grid, other sizes or another split axis (alltoallv from intersected ownership ranges).

  The pattern is cached for each pair of distributions. Redistribution is always explicit. It is a non-fusible, non-blocking plan node, not a trigger, and it reuses the ghost machinery: generated pack, messages, generated unpack, and an event at the end. Work that does not depend on it keeps running.
- **Communication interface.** `tl::communicator` offers `rank`, `size`, `dup`, `split` and a congruence test. It also has three pattern factories called once when the plan is built and cached with it: `halo_pattern`, `reduce_pattern` and `exchange_pattern` (alltoallv, gatherv, allgatherv). Each pattern has `start(buffers)` and `complete(request) -> event`. Raw point-to-point serves the strict tree. The MPI implementation uses MPI 4 persistent and neighbourhood collectives and falls back to non-persistent calls; Kokkos Comm and NCCL or RCCL can implement the same interface later. A `self` communicator without MPI serves one rank and serial builds: local copies, reductions that return their input, redistributions that copy.
- **Progress.** One tensorlib progress thread per rank waits on pack events, starts patterns, tests requests and signals completion. Device queues wait through host-signalled events when the backend declares them; otherwise the thread launches the dependent kernels. `TL_COMM_PROGRESS=thread|caller` selects the mode, and `caller` drives the plan on the trigger thread, for MPI without `MPI_THREAD_MULTIPLE` and for debugging. The communication implementation uses GPU-aware MPI when it detects it (or is told to), and pinned host staging through the backend's copies otherwise. That choice is local. Stream-triggered communication is a later backend capability.
- **Determinism.** Every decision that changes a message depends only on the recorded operations, the distributions and global settings read at start-up (`TL_FP`, kernel-size ceilings). It never depends on local extents, timings, local memory pressure or memory space. The kernel split, pack fusion, staging and progress mode are local by construction. A 64-bit hash of the window's communication plan, computed incrementally like the plan key, travels in every ghost header and packed reduction. A mismatch raises `tl::spmd_error` on the ranks that see it, instead of exchanging the wrong bands. The `collectives` check of [Error reporting and debug mode](24-error-reporting-and-debug-mode.md) compares the hash across ranks before anything launches and checks that every rank received the same bits from each reduction. It names the first divergent node and its sites.

Grilling log (2026-10-30 and 2026-10-31):

- Q1 refresh timing: option C. An exchange exists only if a kernel of the evaluated window reads stale ghosts; when the writer is in the same window, the send is moved right after the writer (boundary band first, send, interior); otherwise posted before the reader. No exchange stays in flight past an evaluation.
- Q2 overlap split: option C. Split into interior and boundary launches when the interior cell count passes `TL_OVERLAP_MIN_CELLS` (per-backend default, `TL_OVERLAP=always|never|auto`); local decision taken at launch from extents, both orderings in the cached plan; it never changes the messages, so it need not match across ranks.
- Q3 aggregation: option B. One message per neighbour per exchange point: every exchange that Q1 places at the same plan point and that goes to the same neighbours (congruent communicator, same process grid, ghost widths may differ) shares it; exchanges at different points stay separate, no send is delayed.
- Q4 packing: option B in v1, C later. Generated pack and unpack kernels (ordinary kernel IR, cached), one pack per exchange point covering every tensor and neighbour of the message; contiguous buffers from the memory resource; message format (poison header, band order) owned by tensorlib. Later optimisation without interface change: pack fused into the writer boundary launch as extra stores.
- Q5 neighbours: option A. One phase, direct messages to every neighbour of the stencil shape (2d for star, 3^d - 1 for box), all posted and waited together; a neighbour that is the rank itself (periodic axis with one rank) becomes a local copy kernel. Dimension sweeps may be added later behind the interface.
- Q6 reductions: option C. One non-blocking collective per plan point packing every reduction whose local result is ready there, plus the poison status word (OR); combined by a tensorlib-defined operation generated from the combiners; completion is an event, consumers such as a 0-d `dt` stay on the device; local results go through the host in v1.
- Q7 reproducibility: option C. MPI non-blocking allreduce with the non-commutative tensorlib operation by default; a fixed-shape binary tree in rank order then a broadcast, over point-to-point, under `TL_FP=strict` or `tl::deterministic(...)`; a debug check verifies that every rank received the same bits.
- Q8 redistribution: option B. v1 covers replicated to block (no communication), block to replicated (allgatherv), block to local on one rank and back (gatherv, scatterv), block to block with another grid, sizes or split axis (alltoallv from intersected ownership ranges, pattern cached per distribution pair); a non-fusible, non-blocking plan node built from the ghost machinery (generated pack, messages, generated unpack, event), not a trigger.
- Q9 interface: option C. `tl::communicator` with rank, size, dup, split and congruence; persistent patterns built once with the plan and cached with it (`halo_pattern`, `reduce_pattern`, `exchange_pattern` for alltoallv, gatherv, allgatherv), each started per evaluation and completed as an event; raw point-to-point for the fixed tree of Q7; MPI implementation on MPI 4 persistent and neighbourhood collectives with a non-persistent fallback; a `self` communicator without MPI for one rank and serial builds (local copies, identity reductions).
- Q10 progress: option B, C later as a capability. One tensorlib progress thread per rank waits on pack events, starts patterns, tests requests and signals completion; device queues wait through host-signalled events when the backend declares them, otherwise the thread launches the dependent kernels; `TL_COMM_PROGRESS=thread|caller` (caller drives the plan on the trigger thread, for MPI without THREAD_MULTIPLE and for debugging); GPU-aware MPI when detected, otherwise staging through pinned host buffers, a local choice.
- Q11 determinism: option C. Rule: decisions that change messages depend only on the recorded operations, the distributions and global settings read at start-up, never on local extents, timings, local memory pressure or memory space. A 64-bit hash of the window communication plan rides in every ghost header and packed reduction (min/max), so a mismatch raises `tl::spmd_error`; the `collectives` debug check compares the hash across ranks before launching and checks that reduction results have the same bits on every rank.
