# Views and slicing

Type: grilling
Status: resolved
Blocked by: 13, 25

## Question

Which view operations does tensorlib offer, and how do they behave with fusion and copy-on-write? [Broadcasting design](13-broadcasting-design.md) fixed one affine index map per kernel operand, covering strided slices, transposes and stencil shifts. Decide the slicing API (NumPy-like `a(range(1, n-1), all)`, `xt::view`-style, or both), which views are writable, how stencil codes express shifted views (`a(i+1) - a(i-1)` over interior ranges, and later halos), what happens with non-affine access (boolean masks, integer gather and scatter) that no affine map can express, and how writing through a view interacts with copy-on-write ([ADR 0001](../../../docs/adr/0001-value-semantics-with-copy-on-write.md)) and the pending window.

Requirements from [Reconcile the core with samurai and ponio](26-reconcile-with-samurai-ponio.md): writable views built from interval tables (samurai's `field(level, i, j)`, the user-facing form of segmented iteration spaces), in-place assignment through them without breaking copy-on-write, and `uint8` tags with bitwise masks.

## Answer

Decided with the user on 2026-10-30. Vocabulary (view, box, segment space) is in `CONTEXT.md`. The view type and the accumulating `+=` are recorded in [ADR 0006](../../../docs/adr/0006-views-are-references-distinct-from-tensors.md).

- **View type.** Slicing returns `tl::view<T, Rank>`, a reference type. Copying a view gives another view of the same owner, assigning writes elements, and the view holds a shared reference to its owner's state, so it never dangles. A `tl::tensor` converts implicitly to a view of itself, so `tl::view<T>` is the type of output parameters: `f(double t, const tl::tensor<double>& y, tl::view<double> dy)`. `tl::tensor<T> t = v` makes a value that shares the buffer copy-on-write, with offset and strides, while the view is affine. Both types satisfy a `tl::tensor_like` concept.
- **Slicing syntax.** Everything goes through `operator()` with Array API semantics. As many integers as the rank read one element, a host read and therefore a trigger. Anything else returns a view: an integer drops its axis, and missing indices are `tl::all` on the right, so `u(3)` is row 3 (xtensor reads an element there, and the different return type turns that into a compile error). The vocabulary is `tl::range(start, stop, step = 1)`, `tl::all`, `tl::newaxis` and `tl::ellipsis`, with negative indices counted from the end. An out-of-bounds range is an error at node build, where NumPy would clamp.
- **Writes through views.** A write that covers every element of the owner with the identity map is a full assignment and follows [Buffer reuse and allocation](21-buffer-reuse-and-allocation.md), so old values are never read (ponio's `dy`). A partial write on a uniquely held buffer writes the region in place. A partial write on a shared buffer detaches it in one fused pass, writing new values inside the region and copying old values elsewhere. All partial writes to one owner in a window (interior, left and right boundaries) share one detach, and their regions become segments of the iteration space. Debug mode lists detaches by source line.
- **Stencils.** `tl::box` holds one range per axis. `u(I)` is a view, `I + tl::offset{dy, dx}` shifts the box, and `tl::interior(u, w)` gives the interior at width `w`. A box reduces to the same affine views as slices, so it adds nothing to the IR. On a partitioned tensor the box is in global coordinates. A shift beyond the local part reads the ghost region when its width covers the shift, with the exchange inserted by [ADR 0004](../../../docs/adr/0004-automatic-ghost-updates-in-the-graph.md); a wider shift is an error at node build that names the axis. Periodicity comes from the distribution. There is no dedicated stencil operator: tiling belongs to kernel lowering. The names may still change with the style rules of the spec.
- **Non-affine access.**
  - `u(mask)` is a write-only target. `u(mask) = e` is a partial write, fused as an in-place `where`. Reading it fails to compile, because its size depends on the data. Extraction goes through `tl::compress(u, mask)`, a non-fusible node that evaluates the mask first; it is a trigger, collective on partitioned tensors.
  - `u(idx)` with an integer tensor reads as a fusible gather shaped like `idx`. `u(idx) = e` is a scatter, where duplicates are an error in debug mode and unspecified otherwise. `u(idx) += e` and `-=` accumulate duplicates (scatter-add, atomics or colouring chosen by lowering), unlike NumPy.
  - Integer tensors have the Array API bitwise operators (`& | ^ ~ << >>`), and comparisons give `tensor<bool>`, which covers samurai's `uint8` tags: `u((tag & keep) != 0) = ...`.
- **Segmented views.** `tl::segment_space S(lengths)` is built once per mesh subset and rebuilt at every adaptation. `S.on(offsets, stride)` gives a writable view, with one `int64` base offset per segment and a stride. Views built on the same space are congruent by identity, an O(1) check; views from different spaces are an error at node build. The kernel gets the lengths once and one offset table per operand, and the tables live on the device. Trailing axes stay ordinary, as in `u(S.on(off, 1), tl::all)` for an AoS vector field. samurai can wrap `S.on(...)` in its `field(level, 2 * i)`.
- **Partitioned tensors.** A slice restricts the owner's distribution: each rank keeps the intersection of its part with the slice, empty local parts are legal, and nothing is communicated. An integer on a partitioned axis removes that axis from the process grid. Views of partitioned tensors are collective. Reading one element of a partitioned tensor is a collective trigger, where the owner broadcasts the value to every rank.
- **Shape changes.** `permute_dims`, `matrix_transpose`, `flip` (negative stride), `squeeze` and `expand_dims` return writable views. `reshape` always returns a value: zero-copy through copy-on-write when the strides allow, a fusible copy otherwise. Writes into the result never reach the source. A `reshape` that mixes a partitioned axis with another is an error that suggests `redistribute()`.
- **Follows from the above.** Slicing a `tl::expr` gives a `tl::expr`, read-only. Affine views export without copy (DLPack with strides, Kokkos `LayoutStride`, mdspan); segmented, masked and indirect views must first be assigned to a `tl::tensor`.
- **Passed on:**
  - [Kernel IR](22-kernel-ir.md): indirect loads (gather), scatter and scatter-add from index views, masked writes as in-place `where`, negative strides, segment lengths shared by all operands with one offset table per operand, and fused detach of partial writes whose regions become segments;
  - [Error reporting and debug mode](24-error-reporting-and-debug-mode.md): listing detaches by source line, duplicate indices in a scatter, and counting element reads of partitioned tensors per source line;
  - fog "Shape of the ABI and of the bindings": whether `a[idx] += v` in Python follows tensorlib or NumPy.
