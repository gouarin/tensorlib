# One C ABI for every binding, with explicit contexts and generic dispatch

Python, Julia and Rust all reach tensorlib through one C ABI, the `c` component (`<tl/c.h>`, C11, target `tensorlib::c`). A Python binding may use nanobind or Cython, but only to wrap that ABI, never to bind the C++ types. The ABI has one opaque, refcounted tensor handle (a value or a view) and no expressions. Every call that records or triggers takes an explicit `tl_context*`, which owns the pending window and the last error. A context is used from one thread at a time and may move between threads. Array operations do not get one C function each: they go through `tl_apply` on an operation handle looked up once in a catalogue that the C++ registry generates. A fixed core of explicit functions covers what has its own semantics: lifetime, metadata, creation, views and assignment, evaluation, DLPack, errors and version.

We rejected binding Python with nanobind over the C++ API, beside a C ABI for Julia and Rust. Two surfaces would drift apart in their threading, error and indexing semantics. The Python module would also depend on the compiler and the exact tensorlib build, while [ADR 0011](0011-thin-templates-over-an-erased-core-and-layered-extension-points.md) puts binary stability in the C ABI only. We rejected keeping the window per OS thread at the ABI, because Julia tasks and async Rust migrate between threads after a suspension point. With per-thread windows, a value recorded on one thread and read from another evaluates the wrong window, with no error. We rejected one C function per operation, because it duplicates about 250 C++ functions by hand. It also leaves no way to reach the library operations, external functions and traced functions that users register at run time.

## Consequences

- Inside tensorlib, the pending window of [ADR 0002](0002-implicit-pending-windows.md) belongs to a context. Each C++ host thread has an implicit context, so the C++ API does not change.
- `tl_retain` and `tl_release` are atomic and safe from any thread, including the finalizers of Julia, free-threaded Python and Rust `Drop`. A release never locks the window: it sets an atomic "dead output" flag that the window reads at evaluation.
- A misspelt operation or attribute is caught at run time (`TL_INVALID_ARGUMENT`) instead of at link time. The catalogue gives each operation's name, arity and attribute schema, so bindings can generate their wrappers from it.
- The ABI grows only by addition. `tl_abi_version()` returns major.minor, and optional components are detected by query. A binding built against one minor version runs on any later one with the same major version.
